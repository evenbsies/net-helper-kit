# 已验证什么，还不能保证什么

## 已通过的检查

`./tests/run.sh` 已实际执行，通过 ShellCheck、shell 语法检查和 **41 项离线回归测试**。测试过程的随机密码、测试证书与二进制夹具写在临时目录，不放进源码仓库。

覆盖内容包括：NAT 内外 UDP 端口分离、随机密码与 URI 一致性、自签证书固定 SHA-256 指纹、私有文件权限、计划完整性校验、拒绝损坏或符号链接计划、拒绝覆盖已有输出、危险输入/端口/路径校验、输入中断、域名规则校验和 5000 条上限、BusyBox `sh`、已有证书名称/私钥匹配，以及健康检查必须检查实际应用而非仅检查监督器。

测试还启动真实 dnsmasq 进程，验证被屏蔽域名及其子域名的 **A、AAAA 和 HTTPS（类型 65）查询均返回 NXDOMAIN**。这些查询只发到本地临时端口，不依赖外部 DNS 正常工作。

## 一键入口测试

`setup.sh` 新增 8 项离线检查，覆盖两种调用方式的帮助、非法参数、受限离线菜单、禁止离线模式调用 apk/curl、真实计划生成、私密权限、拒绝覆盖与默认部署前置拒绝。在当前 Ubuntu 环境还分别以普通用户和 root 手动验证拒绝路径，未安装依赖或启动服务。尚未在全新 Alpine 上实测这条完整搭建链路，不把离线通过描述为生产搭建成功。

## 共享子域名测试

通过本地 mock curl（不访问真实 DuckDNS 账号）验证真实 `shared-plan` 子进程生成计划、共享主机名写入客户端、GET 请求与首参数禁用 curl 配置、token 不进入进程参数和控制台、UUID 和中横线 slug 校验、私网 IP 拒绝、路径别名/符号链接/源码树隔离、拒绝覆盖、profile 权限、API 异常/超时以及计划失败后保留 profile。分步菜单入口也有独立回归测试。

这是离线接口与逻辑验证，**没有验证真实域名申请、真实 API 更新、DNS 传播、长期服务稳定性或公网 UDP 连接**。新版重命名后的 Alpine 安装生命周期未重新实测。

## 旧版做过的 Alpine 实际进程验证

重命名前的版本在沙盒中的一次性 Alpine **3.24.2 x86_64 根文件系统**里，使用 OpenRC **0.63.2-r0**、dnsmasq **2.92_p2-r0**、官方 Hysteria **2.13.0 linux-amd64** 做过以下验证：

- 真实安装，启动两个独立 OpenRC 服务，DNS 和代理均使用非 root 专用账号。
- 官方客户端使用固定证书指纹建立连接，经 SOCKS5 访问本地 HTTP 测试服务。
- 通过 SOCKS5 传递被屏蔽的域名，服务端 DNS 拒绝解析，客户端请求失败而不是超时。
- 客户端配置错误证书指纹时拒绝连接。
- 再次安装会被拒绝，原有证书私钥保持不变。
- 卸载停止服务并移除程序，保留私有配置。
- 在配置中故意注入 YAML 错误后，安装检测到应用未就绪，并清理本次创建的服务、程序和配置。apk 包与专用账号按设计保留。

故障注入曾发现 OpenRC 监督器还在运行时，应用可能已经退出；现在安装与 `status` 都额外检查实际子进程。这是启动时健康检查，不是持续的业务探测，也不验证 NAT 公网可达性。

上述环境是 **chroot + 沙盒宿主内核/网络**，不是完整虚拟机，也不是安全隔离边界。OpenRC 关于 cgroup 权限及最小系统缺少部分启动服务的警告，不代表本项目设置了硬内存限制。

## 在自己的测试环境复现

普通离线测试需要 Python 3、OpenSSL、ShellCheck、dnsmasq、BusyBox 和标准 shell 工具。在 Ubuntu 测试机可安装 `shellcheck dnsmasq-base busybox-static`；在 Alpine 测试机可安装 `python3 openssl shellcheck dnsmasq`。这些测试依赖不要求装在目标小内存 VPS 上。

```sh
./tests/run.sh
```

项目另提供两个**显式选择执行**的集成测试，不在 GitHub Actions 中自动运行：

1. `tests/alpine-lifecycle.sh /绝对/私有计划`：只能在全新、一次性的 Alpine 测试根目录中执行。测试根目录必须已经准备好 OpenRC、procfs、设备节点和网络，并预先放置 `/.nhk-disposable-test-root` 标记。执行时还必须设置 `NHK_DISPOSABLE_ROOT=YES`。它会真实安装、启动、卸载、故障注入并删除刚创建的测试账号，**不要在生产 VPS 或日常系统上运行，也不要为了绕过保护在那里创建标记**。私有测试记录保留在临时目录。
2. `python3 tests/e2e_client.py /可信/hysteria /私有/client.json`：在已运行的一次性本地服务上，检查代理、DNS 屏蔽和错误指纹拒绝。仅接受客户端端点为 `127.0.0.1` 的测试配置，需要 `curl` 和默认屏蔽规则；二进制必须事先取得并核验，脚本不下载它。测试会访问本地 HTTP 服务，并把测试域名交给本地服务端处理。

请保持一次性测试网络没有与本项目测试端口冲突的其他监听服务。不要把私有计划或测试日志添加到源码包或提交到 Git。

## 还没有验证

**没有访问或修改现有生产 VPS，没有发布到 GitHub。** 也没有验证真实 NAT 公网 UDP 转发、不同运营商连通性、全设备 DNS 防绕过、全部第三方客户端或 arm64 平台。

**没有在 64 MB 内存限制下做压力、并发、长期运行或 OOM 测试。** 小缓存、较小 QUIC 窗口与 `GOMEMLIMIT=24MiB` 只是实验性配置；后者不是 RSS 上限，无法保证系统不会 OOM。不要把本地成功启动等同于生产可用性或完整去广告效果。
